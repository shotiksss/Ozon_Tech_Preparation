
Модуль 1: Продвинутый C# и основы платформы .NET (10 уроков)

В колледже вам дают синтаксис, ваша задача — понять, как язык работает под капотом.
• Урок 1: Объектно-ориентированное программирование (ООП) на практике.
	• Теория: Разница между интерфейсами (interface) и абстрактными классами (abstract class). Модификаторы доступа. Принципы SOLID (хотя бы основы: S, O, D).
	• Практика: Спроектировать иерархию классов для интернет-магазина (Товар, Заказ, Доставка, Пользователь).
• Урок 2: Управление памятью: Ссылочные и значимые типы.
	• Теория: Стек (Stack) и Куча (Heap). Типы Value types (struct) и Reference types (class). Передача параметров по ссылке (ref, out, in).
	• Практика: Написать тесты/консольные примеры, демонстрирующие копирование объектов и структур, понять разницу.
• Урок 3: Сборщик мусора (Garbage Collector) и ресурсы.
	• Теория: Как работает GC в .NET (поколения 0, 1, 2). Освобождение неуправляемых ресурсов. Интерфейс IDisposable и конструкция using.
	• Практика: Реализовать класс, работающий с условным файлом или сетевым ресурсом, с правильным внедрением IDisposable.
• Урок 4: Коллекции и Generics (Обобщения).
	• Теория: Устройство List<T>, Dictionary<TKey, TValue>, HashSet<T>. Сложность операций (O(1) vs O(N)). Зачем нужны дженерики.
	• Практика: Написать программу, которая удаляет дубликаты из огромного списка строк, оптимизировав её по скорости с помощью HashSet.
• Урок 5: LINQ (Language Integrated Query).
	• Теория: Лямбда-выражения. Отложенное выполнение (Deferred Execution). Основные методы: Where, Select, OrderBy, GroupBy, SelectMany, ToDictionary.
	• Практика: Написать 10 сложных фильтраций и группировок над массивом данных (например, найти топ-3 самых дорогих заказа для каждого клиента).
• Урок 6: Обработка ошибок и Исключения.
	• Теория: Иерархия Exception. Конструкция try-catch-finally. Создание кастомных исключений. Правило: не использовать exceptions для контроля логики.
	• Практика: Написать валидатор входящих данных пользователя, который выбрасывает кастомные ошибки при некорректном e-mail или возрасте.
• Урок 7: Делегаты, События и Action/Func.
	• Теория: Что такое указатель на метод. Делегаты Action, Func, Predicate. Как работают события (event).
	• Практика: Написать паттерн "Издатель-Подписчик" (например, система уведомлений отправляет SMS, когда статус заказа меняется).
• Урок 8: Асинхронное программирование (Async/Await).
	• Теория: Разница между многопоточностью и асинхронностью. Task и ValueTask. Как async/await освобождает потоки ввода-вывода (I/O bound операции).
	• Практика: Написать симулятор скачивания файлов из сети: несколько файлов качаются параллельно и асинхронно без блокировки главного потока.
• Урок 9: Многопоточность и синхронизация.
	• Теория: Потоки (Thread, ThreadPool). Проблема состояния гонки (Race Condition). Конструкция lock, Monitor, SemaphoreSlim. Concurrent коллекции.
	• Практика: Написать безопасный счетчик, к которому одновременно обращаются 100 потоков, используя lock или Interlocked.
• Урок 10: Профессиональная экосистема: Git и логирование.
	• Теория: Git: коммиты, ветвление (branch), слияние (merge), разрешение конфликтов. Логирование: зачем нужны логи, библиотека Serilog или NLog.
	• Практика: Опубликовать весь написанный код на GitHub. Настроить логирование в консоль и файл для своих предыдущих задач.

Модуль 2: Базы данных и PostgreSQL (6 уроков)

В Ozon Tech миллиарды записей. Нужно уметь работать с БД эффективно.
• Урок 11: Реляционная модель и Проектирование БД.
	• Теория: СУБД PostgreSQL. Таблицы, связи (1:1, 1:M, M:M), внешние ключи (Foreign Keys). Нормальные формы (1НФ, 2НФ, 3НФ).
	• Практика: Спроектировать схему БД для Ozon (Таблицы: Продукты, Категории, Корзина, Заказы, Склады).
• Урок 12: Продвинутый SQL: Выборка и Объединения.
	• Теория: Операторы INNER JOIN, LEFT JOIN, RIGHT JOIN, FULL JOIN. Фильтрация WHERE vs HAVING.
	• Практика: Написать запросы, собирающие статистику: "вывести все категории товаров, в которых за прошлый месяц не было куплено ни одного товара".
• Урок 13: Группировки и подзапросы.
	• Теория: GROUP BY, AGREGATE функции (SUM, AVG, COUNT). Подзапросы (Subqueries) и обобщенные табличные выражения (WITH / CTE).
	• Практика: Написать SQL-запрос для вычисления среднего чека пользователя за всё время.
• Урок 14: Индексы в PostgreSQL.
	• Теория: Как устроена структура B-Tree. Зачем нужны индексы, как они ускоряют SELECT и замедляют INSERT/UPDATE. Понятие EXPLAIN ANALYZE.
	• Практика: Создать таблицу на миллион строк. Замерить скорость поиска без индекса и с индексом с помощью EXPLAIN.
• Урок 15: Транзакции и ACID.
	• Теория: Понятие транзакции (BEGIN, COMMIT, ROLLBACK). Принципы ACID. Уровни изоляции транзакций и проблемы (грязное чтение, фантомное чтение).
	• Практика: Написать SQL-скрипт перевода денег со счета на счет (списание у одного, зачисление другому) внутри одной транзакции с обработкой ошибок.
• Урок 16: Работа с БД из C#: ADO.NET и Dapper.
	• Теория: Как C# общается с БД. Драйвер Npgsql. Micro-ORM Dapper (почему в высоконагруженных системах часто выбирают его, а не тяжелый Entity Framework).
	• Практика: Написать консольное C# приложение, которое подключается к вашей PostgreSQL, вытягивает данные через Dapper и маппит их в C# объекты.

Модуль 3: Разработка Web API на ASP.NET Core (6 уроков)

Переходим к созданию бэкенда — основы того, чем занимаются в Ozon Tech.
• Урок 17: Архитектура Веба: HTTP и REST.
	• Теория: Клиент-серверное взаимодействие. Протокол HTTP (Методы GET, POST, PUT, DELETE; заголовки, коды ответов 2xx, 4xx, 5xx). Концепция REST API. Формат JSON.
	• Практика: С помощью утилиты Postman или cURL поделать запросы к любому открытому публичному API (например, погоды или GitHub API).
• Урок 18: Создание первого ASP.NET Core Web API.
	• Теория: Структура проекта в .NET 8/9 (Program.cs, Мидлвары / Middleware, Контроллеры). Маршрутизация (Routing).
	• Практика: Создать пустой проект Web API. Написать контроллер ProductsController с CRUD-операциями (создать, прочитать, обновить, удалить товар) пока что в оперативной памяти (в List<T>).
• Урок 19: Внедрение зависимостей (Dependency Injection / DI).
	• Теория: Паттерн DI и принцип Инверсии зависимостей (D из SOLID). Время жизни зависимостей в ASP.NET Core: Transient, Scoped, Singleton.
	• Практика: Вынести логику управления товарами в отдельный сервис ProductService, зарегистрировать его в DI-контейнере и внедрить в контроллер через конструктор.
• Урок 20: Интеграция Web API с Базой Данных.
	• Теория: Подключение слоя данных к веб-сервису. Конфигурация строк подключения (appsettings.json).
	• Практика: Переписать ваш ProductService так, чтобы он с помощью Dapper (или Entity Framework Core, если захотите изучить) сохранял и читал товары из реальной PostgreSQL.
• Урок 21: Валидация и обработка ошибок в API.
	• Теория: Валидация входящих моделей (библиотека FluentValidation). Глобальный перехват исключений через Middleware, чтобы пользователю не возвращался сырой StackTrace ошибки.
	• Практика: Запретить добавлять товары с отрицательной ценой или пустым именем. При ошибке возвращать красивый JSON с кодом 400 Bad Request.
• Урок 22: Документирование API (Swagger) и Покрытие тестами.
	• Теория: Что такое OpenAPI/Swagger и зачем он фронтендерам. Основы Unit-тестирования (фреймворк xUnit или NUnit), концепция Mock-объектов.
	• Практика: Настроить Swagger. Написать 3–5 юнит-тестов для бизнес-логики вашего сервиса.

Модуль 4: Микросервисы, Инфраструктура и Высокие нагрузки (8 уроков)

Темы, которые отличают обычного стажера от "кандидата нарасхват".
• Урок 23: Контейнеризация и Docker.
	• Теория: Что такое Docker, зачем нужны контейнеры. Разница между образом (Image) и контейнером (Container). Написание Dockerfile.
	• Практика: Написать Dockerfile для своего Web API, собрать образ и запустить его в контейнере локально.
• Урок 24: Docker Compose.
	• Теория: Как запустить приложение и базу данных вместе. Написание docker-compose.yml. Сети в Docker.
	• Практика: Написать один compose-файл, который одной командой поднимает и ваше .NET приложение, и готовую базу данных PostgreSQL, автоматически связывая их.
• Урок 25: Кэширование с Redis.
	• Теория: Зачем нужно кэширование в e-commerce. Память vs Диск. СУБД Redis (структура Key-Value). Стратегия Cache-Aside.
	• Практика: Добавить Redis в свой проект. При запросе товара сначала искать его в кэше Redis, если его там нет — идти в PostgreSQL, сохранять в Redis и отдавать пользователю.
• Урок 26: Брокеры сообщений: Концепция и Apache Kafka.
	• Теория: Зачем микросервисам общаться асинхронно. Паттерн Pub/Sub (Издатель-Подписчик). Устройство Kafka (Topics, Partitions, Producers, Consumers).
	• Практика: Установить Kafka через Docker. Написать простейшую консольную утилиту-Producer, отправляющую сообщения, и утилиту-Consumer, принимающую их.
• Урок 27: Интеграция Kafka в Web API.
	• Теория: Event-driven архитектура (архитектура, управляемая событиями). Пример: при создании заказа сервис заказов бросает событие в Kafka, а сервис уведомлений его ловит.
	• Практика: При покупке товара в вашем Web API отправлять сообщение "Товар X куплен" в Kafka.
• Урок 28: gRPC vs REST.
	• Теория: Протокол gRPC, разработанный Google (работает по HTTP/2, передает бинарные данные через Protocol Buffers). Почему Ozon Tech использует его для внутреннего общения между микросервисами.
	• Практика: Создать микросервис №2 (например, Сервис Скидок), который общается с вашим основным Web API по gRPC.
• Урок 29: Алгоритмы для собеседования (LeetCode).
	• Теория: Оценка сложности алгоритмов Big O (O(1), O(N), \(O(N \log N)\)). Базовые алгоритмы: бинарный поиск, два указателя, скользящее окно, сортировки.
	• Практика: Решать по 2 задачи в неделю на LeetCode параллельно со всем курсом. К этому уроку у вас должно быть сдано ~40–50 задач уровня Easy.
• Урок 30: Финальный Пет-Проект и Резюме.
	• Практика: Объединить всё изученное в один крупный проект. Архитектура: 2 микросервиса (один REST API, второй внутренний gRPC), база PostgreSQL, кэш Redis, связь через Kafka. Всё запускается через docker-compose up. Ссылка на этот проект вставляется в самый верх вашего резюме.
